## [1.20.0] - 2026-08-20 (August 2026)

### Fixed
- Blizzard's Housing Dashboard no longer opens blank. VE asked the game for your
  house list a couple of seconds after you logged in, and that request quietly
  broke the dashboard for anyone who had not opened it yet: the game hands the
  list to the dashboard's house dropdown, which then only passes it along when the
  list changes, so the panel you opened later was left waiting for something that
  had already been and gone. The dropdown still showed your house name, which is
  why it looked like the panel had simply failed to draw. VE now asks only when you
  open its own window, and repairs the dashboard if anything else has already
  tripped it. Thanks to everyone who reported it.

## [1.19.0] - 2026-07-25 (July 2026)

FIXED:
- Large activity logs no longer stutter the game. The Activity feed and the
  Leaderboard built one real frame per entry and repainted every one of them
  on each refresh, so a busy neighborhood's log meant hundreds of frames and a
  full repaint every few seconds. Both lists now recycle a small pool of rows
  and only paint what's on screen, so they cost the same whether the log holds
  20 entries or 2,000.
- Exporting a large activity log to CSV no longer causes a momentary freeze.
- Opening the addon for the first time each session is faster: the
  Leaderboard, Activity, Info and Config panels are now built the first time
  you actually open them instead of all five being built at login.

- House level, XP and coupons no longer read zero for the first couple of
  seconds after login. Your last-known values are remembered per character and
  shown straight away, then replaced as soon as the live data arrives. Each
  character remembers its own house, so an alt never shows another
  character's numbers.
- Fixed a slow memory leak: completed tasks waiting to be matched against a
  coupon gain were only cleaned up when a coupon actually arrived, so tasks
  that award no coupons left entries behind for the rest of the session.
- Switching house no longer leaves the previous neighborhood's entries on
  screen. The Activity feed and Leaderboard skip redundant redraws by checking
  when the activity log last changed, and that marker wasn't being cleared on a
  house switch -- so both tabs decided they were already up to date and kept
  showing the old house's rows (credited to the newly selected house) until
  fresh data happened to arrive.
- Fixed a second frame leak, in the house dropdown: its rows were thrown away
  and rebuilt every time the window opened. They're now reused.
- The tab strip and the dropdown menu now size themselves correctly the first
  time they're built. Text was being measured before it had been drawn, which
  reads as zero width, so tabs could come up collapsed and the dropdown menu
  too narrow for its longest entry.
- Turning on "Show During Combat" while the window was already hidden by combat
  no longer keeps it hidden -- it now reappears when you leave combat.

ADDED:
- The progress bar now has a tooltip explaining the cycle progress and, when
  your completion chest is ready, says so and tells you where to collect it.
  Once the chest is claimed the tooltip stops appearing entirely -- there's
  nothing left to say, so the bar goes quiet for the rest of the cycle.
- Right-click the progress bar to mark the chest as already claimed -- the same
  as /ve claimed, for when you collected it somewhere the addon couldn't see.
  The tooltip only offers this while a chest is actually waiting.

- Task rows no longer cut off the progress count. Tasks that count to a large
  number showed "0/250..." with the real total clipped, because the progress
  column was a fixed width. It now sizes to the number, and the task name gives
  up the space instead of being overlapped.

CHANGED:
- The "chest ready to claim" icon on the progress bar now grows and shrinks as
  it pulses instead of only fading, so it's far harder to miss on the thin bar.
- Leaderboard: the "My Total" summary row now stays pinned above the list
  instead of scrolling away with the rankings.

ADDED:
- New "Show During Combat" setting (Config tab). When enabled, the window
  stays visible in combat instead of auto-hiding -- handy for watching task
  counters tick up mid-fight (thanks Tuulani from WOWKEA for the request).
  Off by default, so the auto-hide behaviour is unchanged unless you opt in.

FIXED:
- Defensive: preemptive guard against Midnight secret-value taint inside
  player housing. C_NeighborhoodInitiative.GetAvailableHouseXP and the
  HOUSE_LEVEL_FAVOR_UPDATED event payload fields (.houseFavor, .houseLevel)
  may return secret-restricted values in housing interior; previously VE fed

  DandersFrames v4.3.8 (see Reference/MIDNIGHT_SECRET_VALUES.md "Production
  guard library" + Case 4). Zero perf overhead on clients without secret
  restrictions enabled.
